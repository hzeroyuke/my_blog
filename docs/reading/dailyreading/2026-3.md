
## 3.2

- [Kimi K2.5](https://arxiv.org/pdf/2602.02276)
	- native multimodal pre-training: 多模态LLM的核心是对齐文本和视觉
		- vision token : text token = 1 : 9
		- MoonVit-3D 统一处理 image & video
		- Decoupled Encoder Process(DEP) 这个是系统上的修改，加速多模态模型的训练
	- parallel agent training
		- Agent Swarm: 一个可训练的Orchestrator + 多个冻结的Sub-Agent，让模型学会调度Sub Agent，并行地解决问题
- [why thinking with image not work](https://zhuanlan.zhihu.com/p/2004556029116060422?share_code=AOx2QB7d3yht&utm_psn=2006817232878071905)
	- 这是一篇知乎的文章，介绍了在Thinking with image的工作中（比如 Deepeyes/thyme/pixel-reasoner）其中甚至丢掉interleaved images，都能保持benchmark没掉点
	- 先介绍一下这类工作，这类工作是让模型Agentic地进行视觉任务的推理，比如模型想要查看图片的细节，会给出坐标，按照这个坐标进行放大，将新的图片纳入到推理过程中，也就是纳入了很多工作，下图来自Deepeyes

![](asset/Pasted%20image%2020260302212404.png)


- 对于人类来说这个行为是非常自然的，图片看不清的时候放大一下，显然可以有很大的帮助，但是在这些工作的RL里面似乎效果不明显，所谓的涨点更像是VLM本身的能力在增强，而不是依赖于调用工具
- 对于LLM来说，Vit会将图像Patchify，实际上LLM所看到的视野和人类并不一样，本身就是经过裁剪的；并且在Vision Encoder+LLM的套路下，RL作用于模型的时候，还是主要在增强模型的世界知识，一些可以通过文本先验获得的信息会优先被LLM学习
- 后续的类似工作，都开始转向外部数据的输入，比如Image Search，毕竟搜索到新的图片信息，对于VLM是有真实的信息增量的
- [这篇论文](https://arxiv.org/pdf/2602.01334)也讲述了类似的事情，在Vision tool-use RL中，LLM其实并未从Tool中获得收益

![](asset/Pasted%20image%2020260302213611.png)

- Kimi的研究人员也表示，专门对于image tool call进行sft相当容易把泛化性变差，将普通的tool call和带有image统一进行RL是更好的选择
- 核心思想在于，对于一张图的旋转裁剪等操作并不能提高VLM的能力，必须引入新的信息，比如Vision Deep Research或者GUI Agent这种

## 3.3

- [diception](https://arxiv.org/pdf/2502.17157)
	- 实现一个general model能够适应各种视觉感知任务，比如分割，深度估计等等，一些常见的专用模型有
		- SAM 分割模型
		- DA 深度估计模型
		- Stable Normal 用于表面法线估计
		- DINO-X 目标检测和理解
		- Unified-IO 统一模型用于视觉，语言和多模态任务
	- 本篇论文采用 stable diffusion 3 medium 的基础模型，将上述所有任务定义为Image2Image的任务，比如深度估计就是将单通道的深度图通过重复通道数变成一个三通道的RGB图像
		- 除了image2image的image输入和文本输入以外，还有一个point embedding，将某个点的坐标进行位置编码然后嵌入，用于在分割任务上，让模型知道该分割哪个物体
	- 参考SD3的架构，可以通过少量文本提示来切换任务
	- 实验表明，该模型训练好了之后，可以通过少量Lora微调，快速适应各种视觉感知任务
